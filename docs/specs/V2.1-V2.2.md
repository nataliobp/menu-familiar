# V2.1–V2.2 implementation and owner QA

The released baseline is `v1.0.0` (`50dccfc`). This supplement governs presentation on the V2 branch where it differs from the archived [V1 visual contract](05-web-ux.md). The existing use cases, routes, transaction/version rules, Madrid week boundaries, historical snapshots, shopping operations and recipe draft/publication rules still apply.

## Implementation plan

1. Establish shared tokens, local SVG icons, navigation, forms, buttons, and a native dialog with ordinary page fallbacks. Resolve category presentation from canonical V1 keys. The existing salads key displays as Amanides.
2. Reflow the dated week and template on phones and tablets. Enhance slot actions and template selection while using the existing server commands. Category saves require the observed template version and update the changed cell and shared version on success. Conflicts require explicit review. Keep V1 move/exchange confirmation and skipped-target safeguards.
3. Share catalogue and picker list patterns. Keep filtered picker rank exact. Group the unfiltered results by primary category within special and meal compatibility tiers. Groups follow the first ranked member. Cross-category recency is subordinate to grouping in that view.
4. Put effective recipe content in dish detail and retain the legacy recipe URL and contextual editor. Keep saved historical content separate from live dish details. Render without a photo slot because V1 has no photo model.
5. Run the full Django suite and the synthetic browser scenarios before local commit. Owner visual QA is a separate gate.

No schema or data migration is needed. Use disposable SQLite databases with synthetic data. Keep the owner reference and all private data out of tracked paths and build inputs. Catalogue renames, recipe/media pipeline, purchasing reminder and network changes are later slices.

## Owner visual QA

Review at 360 and 390 px portrait and 800×480 and 1024×600 landscape. Check the current-day treatment, dated navigation across years, all fourteen tablet slots, and compact module navigation. Dish names wrap in full on phones. Tablet card titles show up to four lines, with the full name available in the accessible label, action sheet and detail. Try the slot action sheet, choosing a category and clearing it, dismissing with no changes, and reviewing a stale edit in a second tab. Review picker tier order, filtered ranking, archived catalogue, and the cooking view with published, draft and missing recipes. Check editing, confirmation, and historical read-only screens. Record owner observations separately before any release decision.

Run `.venv/bin/python scripts/verify-browser.py` with Playwright and Chromium available on the development machine. The script starts a temporary loopback server, migrates a fresh SQLite database, and seeds synthetic records. Set `MENU_BROWSER_SCREENSHOTS` to a temporary directory to retain the viewport captures. The checks cover JavaScript and server-rendered fallback paths, including the existing editable shopping behavior. Use the normal Django test command with a disposable file-backed test database for the concurrency cases.
