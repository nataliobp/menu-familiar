# Menú Familiar V2.3 and V2.4 operations

## Private import

Work on a separate SQLite copy and media directory. Use the matching V2.2 backup procedure before upgrading a V2.2 database. Apply the candidate migrations to the copy before using either V2.3/V2.4 command. Set `DJANGO_DB_PATH` to the absolute path of that database. Recipe photos live in `recipe-photos/` alongside the database by default. Set `DJANGO_RECIPE_PHOTO_ROOT` to an absolute path for a separate private volume. In the existing container layout the default resolves to `/data/recipe-photos`, inside the persistent data mount. The import operator must be able to write the directory. The app process needs read and directory traversal access. Run the CLI under the same data owner or arrange equivalent permissions.

Install Pillow with WebP support in an isolated administration environment that also contains the app dependencies. The import CLI uses Pillow to decode the supplied files. The running app serves validated local files without an image decoder. Keep the private bundle, decoded media, databases, backups and private browser evidence outside the source tree and the Docker build context.

```sh
python manage.py import_recipe_proposals /absolute/private/bundle --dry-run
python manage.py import_recipe_proposals /absolute/private/bundle --apply
```

Newly seeded catalogues record source identities at the time of `import_catalogue`. For a V2.2 catalogue installed by the original CSV importer, supply `--legacy-catalogue /absolute/private/original.csv` on both commands. This authorizes the original importer's explicit seed-ID-to-PK contract for that seed only. The importer checks the exact original name, category keys, meal preference and occasion flag before recording the link. A source mapped to a different dish already, a mismatched legacy identity or name, and missing dishes are reported by source ID. Names alone never resolve a dish. Apply operates on the eligible records after whole-bundle validation. Dry run is the default and previews all 57 source IDs without writing data or media.

The two approved rename rows are checked against their linked source and original names. A catalogue edit recorded since seed linkage also blocks an unapplied rename. The rename receipt prevents reapplying a prior rename after a later owner edit. Existing published and draft recipes stay intact. Newly imported proposals have complete amounts and can contribute to current and future shopping calculations. They are labelled as pending validation on read screens. A subsequent owner publication uses the usual recipe lifecycle and replaces proposal provenance. Past menu and shopping snapshots retain their frozen recipe, category and dish values.

## Media intake

Provide only real assets in the private bundle. For each new photo, change its manifest row from `pending_generation` to `generated` and supply the relative `photos/NN.webp` file, dimensions, byte count and lowercase SHA-256. The file must decode as a single-frame 4:3 WebP within the import size limits. The command validates the entire manifest before applying. Rerun dry run and apply against the intended database. An expanded manifest can attach new media while preserving recipes already in use. The supplied prompts remain private and can support a separate owner-authorized batch.

Photos are stored with immutable, digest-based names. The app serves only files referenced by a linked dish, through its read-only photo route. Absent files collapse from the recipe view and return 404 from the media route. An interrupted import can leave an unreferenced immutable file on disk. It stays private, the next run can reuse it, and backups include only referenced files. Leave referenced originals available when a backup is taking place.

## Backup and restore rehearsal

```sh
python manage.py backup_menu_data /absolute/private/new-backup-directory
```

The command takes an online SQLite snapshot, checks its integrity and copies the exact photo files referenced by that snapshot after checking their hashes. A missing or mismatched referenced photo fails the backup. The output is a new private directory with `menu.sqlite3` and, when present, `recipe-photos/`. A photo file is stored before its database reference can commit, so a snapshot taken during an import can resolve its references.

Restore the pair into a separate private directory and use the matching app version. Point `DJANGO_DB_PATH` to the restored `menu.sqlite3` and let the default media path resolve its sibling, or set `DJANGO_RECIPE_PHOTO_ROOT` to the restored photo directory. Verify `PRAGMA integrity_check`, run Django checks, and open a dish with and without a photo before any owner-approved switch. A rollback to V2.2 needs the matching pre-upgrade database because V2.2 cannot read the extended proposal metadata.

The existing browser suite uses only synthetic data. To verify a disposable copy of the current private 57-dish bundle in Chromium with Playwright, run `python scripts/verify-recipe-browser.py /absolute/qa/menu.sqlite3`. Pass `--screenshots /absolute/qa/new-captures` for owner-local screenshots. This recipe browser check opens the database read-only.
