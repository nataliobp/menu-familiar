# Menú Familiar V2.0.0 release gate

## First permanent installation

Use this path when there is no production configuration or database. Run the installation block once, in a terminal on the Home Server, as the repository owner with authorized sudo access to local Docker and /var/lib. Docker's system service must already be active and enabled at boot. The host must already have 192.168.1.22 on its trusted household interface. This procedure uses the existing network and Docker settings. It scopes Compose to menu-familiar and checks for project leftovers and a listener on port 18766 before starting.

Have these private inputs ready:

- The original 57-dish CSV. The existing ignored PLATOS_57.csv is the default.
- The approved private bundle directory containing recipes-57.json, catalogue-renames.json, photo-manifest.json, and photos/. The manifest must include the 52 approved WebPs and the five pending entries.
- A readable, paired snapshot of the approved QA database and recipe-photos/ directory. Use it only to compare approved names, published recipe content and photo digests against the bundle. Obtain a private copy from the QA owner if needed. The staged production database starts empty and receives its data exclusively through the import commands.
- An owner-private backup directory outside the repository with space for the Docker image archive, database and media. Supply an existing private Python interpreter with the pinned repository requirements and Pillow with WebP support, or let the block create a temporary administration environment using python3 with venv support and package index access. The Docker build also needs access to its base image and dependencies.

The first installation applies the two explicitly approved catalogue name overrides for source IDs 7 and 17. The seeded dish IDs and the stable source IDs stay the same. This matches the approved QA catalogue. The V1 upgrade below uses the name-preserving mode for existing production data.

db = sqlite3.connect("file:/data/menu.sqlite3?mode=ro", uri=True)

### Recovery

Use the recovery block with the verified bootstrap backup if the database has never received household edits. For an established installation, select the newest verified backup with the matching configuration and image. Recovery verifies the staged restore with the matching container before stopping Menú Familiar. It moves the old database and media aside together, then keeps the previous environment in the recovery directory. Run only from the tagged checkout on the Home Server.
